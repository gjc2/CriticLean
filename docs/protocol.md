# DeepSeek 模型替换实验协议

本协议对应工程 **0.2.1**，定义当前工程唯一的实验条件：在 CriticLeanBench 发布的题目和原始提示上，将评审模型替换为 `deepseek-flash`，每题调用一次，直接读取模型的二分类判断。不存在额外的程序语义裁决。

## 1. 目标、输入和完成标准

输入是自然语言数学陈述 NL 与一份候选 Lean 陈述。目标是判断候选是否忠实对应原文，不是生成 Lean、证明题目或验证完整证明。

正式实验覆盖固定公开版本的全部 500 条样本。每条保留一次派发记录；正常返回时提取显式 `Correct` / `Incorrect`，技术失败时保留失败类型；最后对全部有标签样本评分。区分两个完成标准：`status: "complete"` 表示遍历结束；只有每题都取得有效标签，`label_status` 才是 `"complete"`。如果仍有题目没有有效判断，运行保存全部记录后以退出码 3 结束，并明确报告未完成标签数；它不猜标签，也不自动重试。即使全题都有标签，也不等于判断均正确。

程序验证输入格式、来源和记录绑定，以便复核实验；它不验证模型理由，不根据引用是否精确、是否提出疑问或是否给出反例来接受／否决标签。

## 2. 数据版本与标签

数据集：[`m-a-p/CriticLeanBench`](https://huggingface.co/datasets/m-a-p/CriticLeanBench)。

固定 revision：

```text
6225522bce304f62d4907aedb9642255f9417bf0
```

固定 Parquet SHA-256：

```text
baf3e43bcfe0c476114e744b7cde098fe02292a5ab9b0b0fa84dc279f1e203d3
```

数据中的 `refined_statement` 是数学原文，`autoformalization` 是候选 Lean，`messages` 是已发布的评审输入。`tag` 为公开参考标签：

| 原始 tag | 数量 | 评分参考 |
| --- | ---: | --- |
| `compile_right_is_right` | 250 | `Correct` |
| `compile_right_is_false` | 200 | `Incorrect` |
| `compile_false` | 50 | `Incorrect` |

编译失败样本是原基准的一部分。这里保留它们以保持全量评测范围，同时单独报告作者标为编译通过的 450 条。我们没有重新运行 Lean 验证这些编译标签；公开参考也不是本项目重新证明过的数学真值。

数据准备不会创建训练／开发／测试划分。5 条连接测试属于同一基准的子集，不是新的正式留出集。正式结果使用全部 500 条，避免把另一套分割方案混入与原基准的比较。

## 3. 逐字保留作者公开提示

固定版本的 500 条 `messages` 均为单个 `user` 消息。存在两个模板，分别用于 300 条和 200 条；本工程逐条保留，不将其统一成自写提示。

准备阶段验证：

1. 每条消息只有 `role: "user"` 和字符串 `content`，不含历史 assistant 回复。
2. 固定提示前缀属于该版本发布的两个模板之一。
3. 数学原文与 Lean 区块按公开分隔标记出现且顺序正确。
4. 两个区块与原始列内容的哈希绑定一致，仅容许分隔标记引入的边界换行。
5. 区块外不存在额外标签、历史判断或未知指令。

这些验证检查发送内容的来源，不能判断题目是否对应。通过后，**发送的消息内容不经过重新拼写或规范化**：

- 不添加 system prompt 或 `instructions`。
- 不去除 Lean 注释，不修改空白，不展开定义。
- 不加入提示中的例子、工具结果、金标准或先前评审。
- 不附加 API JSON schema、`response_format` 或强制工具调用。
- 不把 `gold.jsonl`、`tag` 或其他原始元数据发送给 DeepSeek。

原题中的答案数值属于候选必须对应的任务内容，不是“这份 Lean 是否正确”的标签。完整 Prompt 可直接查看准备目录的 `author-prompts.jsonl`，以及运行快照 `author-messages.json` 和逐请求 trace。

## 4. 模型与调用条件

模型固定为 `deepseek-flash`；接口固定为 `https://api.deepseek.com/responses`。只从 `DEEPSEEK_API_KEY` 环境变量读取密钥，不加载 `.env`，也不在文件里保存密钥值。`run` 在建立输出目录前拒绝缺失或包含控制字符的密钥；真实 API 返回的身份错误仍保留为技术失败。

唯一正式配置是 `configs/deepseek.json`，`method` 为 `critic_original`。0.2.1 保留 `high` 思考，将每次及每题最大输出设置为 **393216 token（384K）**，即截至 2026-10-20 官方为 `deepseek-flash` 公布的服务端最大输出，是旧版 8192 的 48 倍。[官方模型元数据](https://api-docs.deepseek.com/api/list-models/)明确区分上下文窗口与最大输出，不能把 1M 上下文误当成 1M 输出。

`request_timeout_seconds: null`、`max_wall_seconds_per_case: null` 取消应用设置的请求和每题时长上限；`provider.max_response_bytes: null` 取消原先 2 MiB 响应读取上限。不再主动缩短长思考请求或截断较大的返回体。操作系统、网络和服务端本身仍可能中断连接。

这些参数属于新的 DeepSeek 推理条件，不属于作者发布的逐字提示，也不等同于 CriticLeanGPT 解码设置。明确发送官方最大 `max_output_tokens`；省略参数会采用服务默认值，不能获得无限输出。服务端仍有硬上限，拒绝、错误或格式失败也可能发生，因此不能承诺所有输入最终一定给出判断。原版 8192 预算结果不得被这次升级覆盖。

不发送 `temperature`、`top_p` 或 `seed`；最大输出 token 包括思考 token。接口不支持存储响应，程序不发送 `store` 参数。

每条样本使用独立请求，没有会话记忆，没有工具或 Agent，没有自动重试。最多 500 条请求；5 条连接测试另计。请求、完整返回 JSON、最终回复文本及接口返回的用量被保存，包括服务商实际返回的 reasoning 内容；未返回的内部思考无法保存，记录 reasoning 也不等于验证了推理。

即使模型 ID 相同，服务商仍可能更新其后端实现。记录实际日期、配置、Python／工程版本、可获得的服务端元数据和本地哈希，可以提高可追溯性，但无法冻结远程权重版本。

## 5. 模型标签与技术处理

作者提示要求 `reasons` 和 `is_assistant_correct`。有效模型标签只有大小写准确的 `Correct` / `Incorrect`。程序解析 JSON；必要时只提取回复中唯一显式的 `is_assistant_correct` 字段。`reasons` 内的非法 JSON 转义不应遮蔽回复中可唯一识别的显式标签；修复此类提取兼容性不构成语义改判。无法唯一提取或标签冲突时记录解析失败，不通过理由猜测标签。

内部字段映射为：

```text
Correct   → supported
Incorrect → contradicted
技术失败   → unknown
```

这里的 `supported` / `contradicted` 只是统一记录名称。`unknown` 是 API、截断、请求中断或标签解析失败的技术状态，不是新增第三类评审任务，也不表示程序认为理由不可信。

程序不会：

- 审核 `reasons` 的数学正确性。
- 因为理由空白、引文不精确或仍有疑问而改写一个成功提取的标签。
- 根据公开标签修改模型输出。
- 再请求一个模型判断、投票、回译或要求人工裁决。
- 运行 Lean 编译器、验证证明或以 `sorry` 为错误依据。

原始回复始终保留，便于读者检查标签提取是否忠实。技术失败保留在全量分母里，并单独报告，不能删掉后宣称满覆盖。

## 6. 计费、中断与恢复

本项目不设置美元硬上限，也不自动查询账单。每题一次、总题数和最大输出 token 只限制请求规模；它们不能承诺具体费用。缺失用量或费用为未知，不能记作零。

运行会在派发前写记录，并用 `checkpoint.json` 原子保存权威运行状态和预测；`manifest.json` 与 `predictions.jsonl` 是可读镜像。应一并保留整个目录，勿手动修改检查点或镜像。`--resume` 仅接受相同输入、配置、提示和实现绑定，并保留已完成结果。已派发但缺少完整本地结果的题目记录为中断技术失败，不自动重放，因为服务端可能已经处理和计费。已记录的失败也不会自动重试。

取消本地截止时间可能让单次请求长时间等待；用户主动中断后，仍按派发记录处理，不能假定服务端没有计算或计费。

更改参数或重跑失败题必须用新目录，明确说明这是新增实验。不可将多次回复择优合并为“每题一次”的结果。输出目录是独立、不可手动改写的实验记录；评分在单独目录生成。中断后先执行 `run --resume`，再执行 `evaluate`；评分拒绝未完成的运行或落后镜像，不静默使用不完整结果。

### 旧版截断样本的独立重跑

本工作区旧运行 `deepseek-bench500-v1` 的 52 条截断样本均没有最终显式标签：49 条没有最终回复文本，3 条只有部分文本。原始 trace 指向 `max_output_tokens`，旧版 8192 输出预算包含思考。升级后仍保留旧运行与其 389/500＝77.8% 分数。

`data/deepseek-truncated52-v1/` 仅按该运行的技术截断状态选取，保留输入和消息哈希及选择来源；不用 gold 选题。新请求写入 `runs/deepseek-truncated52-max-v2`。这是失败子集的新预算实验，分母是 52，不能报告成 500 条主结果。全量新条件应使用独立 `runs/deepseek-bench500-max-v2`，每题再请求一次。两者均不得覆盖或择优合并旧单次运行。

## 7. 与论文保持一致的范围

| 可以确认保持的公开部分 | 无法据此宣称一致的部分 |
| --- | --- |
| 固定 500 样本及标签映射 | 私有运行环境与服务端权重版本 |
| 发布数据内每条原始提示 | 未完全公开的精确解码参数 |
| 原始 NL 与 Lean 文本 | 训练、模型架构或 tokenizer |
| 单次二分类评审任务 | 私有评分脚本和所有边界解析行为 |

公开数据的提示版本与论文附录文字不完全相同；本项目明确选择发布数据的 `messages` 作为唯一可执行输入。论文提及的 vLLM 默认参数不能替代精确版本与参数记录，不能推导出 DeepSeek API 和作者本地推理完全等价。

因此结果的准确描述是：**“在 CriticLeanBench 固定公开版本及其原始消息上的 DeepSeek 替换评测”**。可以把 ACC 与论文历史成绩并列，但须注明各自来源和推理条件；不能将它表述为除了权重之外所有实现细节完全一致。

论文表格中的 FPR/FNR 命名存在与标准二分类定义不同的情况，而作者完整评分脚本不可得。本工程给出标准 TP/FP/TN/FN、明确公式和总分母，避免通过猜测表格列名制造精确复现。见[结果说明](results.md)。

## 8. 工程验证与发布边界

`make check` 全部离线，验证原提示保留、标签盲性、单次派发、失败与恢复及评分流程。它没有检验真实 DeepSeek 的检测能力。新版预算需要另行真实运行才能得到模型分数；早期自写 Prompt 的 5 条结果不能回收为原始提示协议分数。

`make release` 和 `make github-dir` 使用源码白名单，不导出本地数据、请求、回复、密钥、环境、模型权重或旧版归档。实际公开实验结果前，应人工检查内容并记录全部失败，不从离线测试推导模型分数。
